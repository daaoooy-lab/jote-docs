## 배경

`2026-07-27-feature-prioritization.md`에서 정리한 Should have 항목들은 순서 없이 나열만 되어 있었음. 각 항목이 다른 항목이나 Must have 인프라에 의존하는지를 기준으로 착수 순서를 정리함.

<br/><br/>

## 단계별 분류

### 1단계 — 비-AI 기본 CRUD/UI
- 키워드 전체 검색
- 즐겨찾기/고정, 폴더 구조
- 체크리스트, 코드 블록 (에디터 확장)
- 이미지 첨부
- 다크모드/테마

Must have의 에디터/저장 포맷만 정해지면 바로 붙일 수 있고, 항목 간 의존성이 없어 병렬 진행도 가능함.

<br/>

### 2단계 — 독립적인 AI 작성 지원
- 메모 요약
- 태그 자동 생성

"선택 텍스트 → LLM 호출 → 결과 삽입"이라는 동일 패턴이라, 이 패턴을 한 번 구축해두면 두 기능 모두 빠르게 붙일 수 있음.

<br/>

### 3단계 — 구조에 얹는 AI
- 메모 자동 분류 / 카테고리 추천

1단계의 폴더 구조가 먼저 있어야 "분류"라는 개념이 의미가 생기고, 결과를 검증하기도 쉬워짐.

<br/>

### 4단계 — 임베딩 인프라 위에 얹는 AI
- 관련 메모 추천

Must have의 "의미 기반 검색" 인프라가 전제 조건이라, 해당 작업이 끝난 이후에나 시작 가능함.

<br/><br/>

## 결정

위 4단계 순서(비-AI 기본 → 독립적 AI 작성 지원 → 구조 기반 AI → 임베딩 기반 AI)로 착수 순서를 확정함.
