## 배경

기획/설계(기능 정의, 기술 스택, 아키텍처, 브랜드 디자인, 협업 컨벤션, 인증 세부사항)가 정리되면서 개발 착수 단계로 넘어가는 시점. 개발을 어떤 순서로 진행할지, 전체 기간을 어떻게 잡을지 정하고 이를 스프린트 단위로 구체화함.

<br/><br/>

## 프론트/백엔드 개발 순서

### 검토한 방식
- **프론트 먼저, 이후 백엔드** — 처음 생각했던 방식
- **완전 동시 진행** — 프론트/백엔드를 매일 병행
- **기능 단위 수직 슬라이스** — 기능 하나를 프론트+백엔드까지 끝까지 붙여서 완성한 뒤 다음 기능으로 이동

<br/>

### 결정: 기능 단위 수직 슬라이스
1인 개발이라는 조건에서 완전 동시 진행은 컨텍스트 스위칭 비용이 크고, 프론트를 먼저 다 만드는 방식은 두 가지 문제가 있음.
- 아키텍처가 "프론트 → NestJS → AI 서비스" 구조라 프론트가 결국 백엔드 API에 붙어야 동작함. 프론트를 먼저 만들면 목업 데이터로 작업하다 나중에 통째로 다시 연결해야 하는 리워크가 생김
- Jote의 프로젝트 목표 자체가 "AI Agent/LLM 기반 기능 구현 경험"이라, 프론트에 먼저 몇 주를 쏟으면 정작 어필하려는 백엔드/AI 역량 작업이 뒤로 밀림

따라서 기능 하나(예: 메모 CRUD)를 프론트+백엔드 다 붙여서 끝까지 동작하게 만들고, 그다음 기능으로 넘어가는 수직 슬라이스 방식으로 진행하기로 함.

<br/><br/>

## 전체 개발 기간

### 현재 상황 확인
기획을 시작한 지 5일째(2026-07-26 ~ 2026-07-30)이며, 이 프로젝트에 거의 전업 수준(주당 30시간+)을 투입할 수 있고 특정 시점까지 완성이 필요한 상황임.

<br/>

### 기간 검토
- **1개월** — Tiptap 에디터, pgvector 기반 임베딩/시맨틱 검색, FastAPI+SSE 스트리밍, RAG 파이프라인 등 처음 써보는 요소가 많아 빠듯함
- **2개월** — Must have 5개 기능에 4~5주, 여기에 Should have 1단계까지 포함하면 8주 선에서 여유 있게 맞출 수 있음

<br/>

### 결정: 2개월(8주), 넉넉하게
개발 착수(2026-07-31) 기준 8주 뒤인 2026-09-24를 목표 완성 시점으로 잡음.

<br/><br/>

## 스프린트 구성

### Sprint 0을 완료된 스프린트로 포함
이미 진행한 기획 5일(2026-07-26 ~ 2026-07-30)을 "Sprint 0 — 기획"으로 스프린트 목록에 포함하고 완료 상태로 표시함. 이후 Sprint 1부터 개발 착수 시점(2026-07-31)에 맞춰 주 단위로 구성함.

<br/>

### Sprint 1(레포 세팅) 범위 논의
처음에는 Sprint 1(레포 세팅)에 한 주 전체를 배정한 것이 길어 보여서, 이슈/PR 템플릿·라벨처럼 "팀원 합류에 대비한" 항목은 뒤로 미루고 핵심(레포 생성, CI, 코드 컨벤션)만 압축해서 2~3일로 줄이는 방안을 검토함.

**결정: 원래 범위(한 주) 유지.** 이슈/PR 템플릿과 라벨은 팀원 협업 목적만이 아니라, 개인 프로젝트 진행 내용을 GitHub 상에 잘 정리해서 포트폴리오로 보여주려는 목적도 있어 미루지 않고 Sprint 1에 그대로 포함하기로 함.

<br/>

### Must have 기능 커버리지 확인
Sprint 2~6까지 Must have 5개 기능(메모 CRUD, 에디터+Markdown, 자동 저장, 시맨틱 검색, AI 채팅)이 모두 배정되어 있고, Sprint 7을 통합 버퍼 주간으로 둬서 늦어도 09/17까지는 Must have 전체가 동작하는 상태를 목표로 함. Should have 2~4단계(AI 작성 지원, 자동 분류, 관련 메모 추천)는 이번 8주 범위에는 포함되지 않고 이후로 넘어감.
